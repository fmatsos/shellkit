# shellkit's visuals

Images are generated by **Codex** (the user's choice), never drawn by hand or taken from
the web. Claude writes the prompt, runs Codex, checks the result, encodes and places it.

## The character

Every image shows the same mascot, as in `docs/assets/banner.png` (always attach it):
an **orange hermit crab**, **black sunglasses** with a beach reflected in them, a **beige
spiral shell** carrying a black **`>_` terminal badge**, often a wrench and a screwdriver.
Style: **funky**, 70s groovy / disco, cartoon sticker, thick dark outlines, sunbursts,
halftone dots. Palette, the site's: orange `#ff6b1a`, magenta `#ff2e88`, teal `#14c4bd`,
yellow `#ffd23f`, navy `#1d1541`, ink `#140f2e`, cream `#fff4e0`. **No text or letters in
an image** (the `>_` badge aside): text goes in HTML, where it's readable and translatable.

## Running Codex

```bash
D=<scratch dir>/visuals; mkdir -p "$D/out"
cp ~/www/config/docs/assets/banner.png "$D/ref-banner.png"
codex exec --skip-git-repo-check -C "$D" -s workspace-write \
  -i "$D/ref-banner.png" [-i <other refs>] - < "$D/prompt.txt" > "$D/codex.log" 2>&1
```

- Run it with `run_in_background`: a batch takes 5 to 25 minutes. Several images per run
  keep the style consistent; one retry per image that fails, not a whole new batch.
- The prompt names each output file (`out/<name>.png`), its size, what to show, and ends
  with "Do not create or edit any other file". Codex also keeps every original, full size,
  in `~/.codex/generated_images/<thread>/exec-*.png`: encode from those, not from a copy
  already compressed.
- **Look at every image** (Read it) before using it: same crab (colors, glasses, badge),
  no garbled text, the style of the others. Say which ones you rejected.
- When done, copy this session's originals and the final sheets to `~/Images/shellkit/`
  (`originals/`, `sprites/`) with `cp -n`, named by their role: the user keeps them there.

## Sprite sheets (animations)

The site plays sheets of **6 frames in one row, 256×256 cells** (1536×256 PNG, RGBA),
shrunk to 768×128 WebP and stepped by CSS (`steps(6)`). Put these hard requirements in
the prompt, word for word, and let Codex enforce them with Pillow:

> Transparent background, no ground, shadow, text or border. Generate each pose so the
> whole character and its prop are visible with transparent margin all around; then scale
> all 6 by the SAME factor so the widest fits in 224 px and the tallest in 240 px, center
> horizontally, align bottoms on y=250. Verify that in every cell alpha is 0 on the 4 px
> border strip and each cell holds one connected figure (drop specks < 200 px). Frame 6
> loops back to frame 1. Write a preview GIF (8 fps).

Without them, raised claws get cut at the cell edges (the first dance sheet was). Then:

```bash
python3 ~/www/config/.claude/skills/visuals/sprite-check.py "$D"/out/crab-*.png   # + *-view.png to Read
```

Existing sheets (`gh-pages:assets/`): `crab-walk` (side view, walking right: the page
flips it), `crab-dance`, `crab-type` (on a laptop), `crab-point` (presenting, to the
right), `crab-read` (a book). A new one: same character, same scale as `crab-dance.png`
(attach it), one clear action that fits the section it will live in.

## Encoding and placing

| Image | Where | Encoding |
|-------|-------|----------|
| banner, prompt screenshot | `main:docs/assets/` (README, docs) | PNG, as is |
| hero | `gh-pages:assets/hero-{640,1200}.{avif,webp}` | AVIF crf 34 (640) / 42 (1200), WebP q70 |
| feature cards | `gh-pages:assets/<name>-{480,800}.{avif,webp}` | a centered **4:3 crop** first, then as the hero |
| sprites | `gh-pages:assets/crab-<name>.webp` | resize to 768×128, WebP q78 (alpha kept) |
| mascot, icons | `mascot-96.webp`, `favicon.png` (64), `apple-touch-icon.png` (180, on cream) | from the transparent mascot |
| Open Graph card | `gh-pages:assets/og.jpg` | 1200×630 JPEG q85 |

```bash
python3 - <<'EOF'   # WebP with Pillow; AVIF with ffmpeg (Pillow here has no AVIF)
from PIL import Image
im = Image.open("ORIG.png").convert("RGB"); w = 800
im.resize((w, round(im.height * w / im.width)), Image.LANCZOS).save("name-800.png")
im.resize((w, round(im.height * w / im.width)), Image.LANCZOS).save("name-800.webp", quality=70, method=6)
EOF
ffmpeg -loglevel error -y -i name-800.png -c:v libaom-av1 -still-picture 1 -crf 34 -cpu-used 4 -pix_fmt yuv420p name-800.avif
```

Keep what the page loads small (the hero is its LCP: ≤ ~50 KB per variant) and give every
`<img>` its `width` / `height`. Then rebuild and check the site: the `website` skill.

## Screenshots

- **The prompt** (`docs/assets/prompt.png`, README and `docs/prompt.md`): the real prompt,
  96 columns, a demo project, the default theme and `SHKIT_FORMAT='{dir} · {git} · {mr}'`
  (the caption in `docs/prompt.md` says so, keep them in step). It must be a render of the
  real prompt, never a generated image: an AI picture would show a prompt that doesn't
  exist. How the current one was made isn't recorded: ask the user before redoing it, and
  keep its look (dark window, traffic lights, title bar, 2× scale). After replacing it,
  bump the `?v=N` cache-buster in both `<img>` and copy it to `gh-pages:assets/prompt.png`.
  On the site's landing page the prompt is HTML (`src/home.html`, `.term`): update its
  segments and `aria-label` to match.
- **The Open Graph card**: an HTML page 1200×630 (the hero original as background, the ink
  sticker with "shellkit" in Shrikhand and a one-line tagline), then
  `google-chrome --headless=new --hide-scrollbars --allow-file-access-from-files --window-size=1200,630 --screenshot=og.png file://…/og.html`,
  converted to JPEG. Check it with `Read`: nothing cut, text readable at thumbnail size.
- **Pages of the site**, to show or to check: headless `--screenshot` (add
  `--force-prefers-reduced-motion` for the final state of the animations), a real Chrome
  when motion matters.

Alt text: every informative image gets one that says what it shows (the crab and what it
does), a decorative sprite `alt=""`. Write it with the image, in the same commit.
